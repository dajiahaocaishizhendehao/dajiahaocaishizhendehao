# IPMS Change Skill

## 何时使用

以下任务必须执行本 Skill：

- 新增或修改专利、软著及其共性主档；
- 修改材料、原件、日期、提醒、费用、发票；
- 修改首页、列表、详情、统计口径；
- 修改权限、审计、导入导出；
- 修改数据库、API、状态或关键字段；
- 修复上述模块中的业务缺陷。

纯粹解释已有代码且不改动仓库时可以不使用。

## 第一步：读取事实源

必须读取：

- `AGENTS.md`；
- `docs/PRODUCT_SPEC.md`；
- `docs/DECISIONS.md`；
- `docs/OPEN_QUESTIONS.md`；
- 所有将要修改的文件；
- 相关测试、迁移和接口契约。

输出事实表，每项标明 `CONFIRMED`、`ASSUMED` 或 `UNKNOWN` 以及来源。引用路径时尽可能带行号。

## 第二步：通过歧义门

遇到下列任一情况必须停止受影响部分并询问用户：

- 字段的含义、必填性或唯一性不明确；
- 专利与软著状态映射不明确；
- 权限、数据范围或删除策略不明确；
- 日期是否为法律期限、如何计算或按哪个法域不明确；
- 费用、税额、发票关系或统计口径不明确；
- 外部接口没有官方契约；
- 变更会破坏已有数据或接口。

只有低风险、局部、容易撤销且不影响业务含义的细节可以设为 `ASSUMED`，并必须在交付时列出。

## 第三步：建立变更契约

编码前写清：

- 输入及校验；
- 输出和错误行为；
- 操作权限和数据范围；
- 数据新增、修改及删除行为；
- 日期、金额、时区和空值语义；
- 审计事件；
- 兼容性和回滚方式；
- 验收样例；
- 明确不做的内容。

## 第四步：领域检查

### 专利与软著

- 共性数据写入主档；专业字段进入各自模型；
- API 不接受不属于该类型的专业字段，或明确忽略策略；
- 类型变更默认禁止，除非存在已确认迁移方案；
- 专业状态不得凭经验映射为综合状态。

### 材料与原件

- 电子材料、原件扫描件和纸质原件概念分离；
- 文件元数据与二进制存储分离；
- 上传、预览、下载、删除均鉴权并审计；
- 版本和哈希规则清晰；
- 删除默认逻辑删除。

### 日期与提醒

- 计划日期、截止日期、实际完成日期、提醒时间分离；
- 法律期限不从模型常识推断；
- 自动生成项标明来源、规则版本和人工确认状态；
- 时区处理与业务日期类型正确。

### 费用与发票

- 金额使用 decimal/定点类型并带币种；
- 应付、实付和发票金额不得混用；
- 发票与费用采用多对多关系时使用关联表；
- 统计页面明确显示统计口径。

### 统计

每个指标必须定义：

1. 来源表或接口；
2. 过滤条件；
3. 使用的日期字段；
4. 去重规则；
5. 状态范围；
6. 空数据行为。

没有定义完整的指标不得开发。

## 第五步：最小实现

- 优先补充验收测试或可执行样例；
- 一次只实现一个可验证的垂直切片；
- 不顺手升级依赖、改框架、重写无关模块；
- 不创建用户未要求的页面、状态或字段；
- 数据库变更必须采用迁移并考虑已有数据；
- 临时占位必须写 `TODO(CONFIRM):`，不得进入完成报告。

## 第六步：测试矩阵

每个业务变更至少评估：

| 场景 | 要求 |
|---|---|
| 正常输入 | 成功并返回正确数据 |
| 必填缺失 | 明确拒绝 |
| 非法枚举/格式 | 明确拒绝 |
| 重复关键编号 | 按已确认规则处理 |
| 类型错配 | 专利字段不能污染软著，反之亦然 |
| 越权访问 | 服务端拒绝并记录适用审计 |
| 空数据 | 返回空集合/空态，不造假数据 |
| 日期边界 | 不混淆 date、时间戳和时区 |
| 金额精度 | 不使用浮点误差模型 |
| 删除与恢复 | 满足逻辑删除及权限规则 |

只测试与任务适用的场景，不适用项标 `N/A`。

## 第七步：真实验证

只运行仓库中实际声明或已确认的命令。按适用情况验证：

1. 格式化检查；
2. lint/静态检查；
3. 类型检查；
4. 单元测试；
5. API/集成测试；
6. 数据库迁移与回滚检查；
7. 构建；
8. 页面实际操作或截图验证。

记录命令、退出码和关键结果。命令不存在就写“未配置”，不得自行宣称通过。

## 第八步：交付

使用 Agent 固定交付格式。以下任一情况存在时不得说“已完成”：

- 核心 `UNKNOWN` 未解决；
- 测试、构建或迁移失败；
- 权限只在前端处理；
- 统计口径未确认；
- 使用 mock 却宣称真实集成；
- 未验证却宣称可运行或可上线。
