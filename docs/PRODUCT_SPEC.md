# 知识产权管理系统产品规格（MVP）

- 版本：0.1
- 状态：需求基线草案
- 更新日期：2026-11-05
- 产品范围：专利、计算机软件著作权、商标/Logo

## 1. 产品定位

本系统是轻量知识产权电子档案系统。核心目标：

1. 集中保存专利、软著和商标/Logo的基础信息；
2. 保存申请材料、通知文件、证书扫描件等电子材料；
3. 登记纸质证书、票据等原件的保管和借还信息；
4. 保存关键日期、提醒事项、费用和发票；
5. 支持查询、Excel 导入导出和后期统计。

系统不替代律师、专利代理师或官方机构，不自动作出法律结论。

## 2. MVP 导航与页面

### 2.1 首页/工作台

展示全部知识产权信息：

- 知识产权总数、专利数、软著数、商标数；
- 已授权专利、已登记软著、已注册商标数量（按档案综合状态统计，不单独统计证书）；
- 本年度新增数；
- 申请/办理中、已取得权利、已失效等综合状态分布；
- 知识产权类型分布；
- 年度新增趋势；
- 即将到期或待处理事项；
- 最近新增档案和材料；
- 新建专利、新建软著、上传材料、登记费用、登记发票、新建提醒快捷入口。

具体统计口径必须在实现前确认并记录，不能以示例数字充当真实数据。

### 2.2 知识产权管理

1. **全部知识产权列表**：统一搜索、筛选、查看专利、软著和商标；
2. **专利列表**：专利专属查询、导入导出；
3. **新建/编辑专利**：维护基础、申请授权、人员、原件和材料信息；
4. **专利详情**：概览及基本信息、日期进度、材料、费用发票、原件、操作记录页签；
5. **软著列表**：软著专属查询、导入导出；
6. **新建/编辑软著**：维护软件、开发发表、登记、权利人、原件和材料信息；
7. **软著详情**：概览及基本信息、日期进度、权利人、材料、费用发票、原件、操作记录页签；
8. **商标/Logo列表**：查看商标图样、名称、注册号、类别、状态和关键日期；
9. **新建/编辑商标**：维护Logo图样、商标文字、申请注册、类别、权利人、代理机构和备注；
10. **商标详情**：概览及基本信息、图样版本、类别、日期、材料、费用发票、操作记录。

不设置独立的“已取得权利/证书台账”页面；已授权/已登记/已注册状态直接由知识产权档案管理，证书扫描件作为材料保存。

### 2.3 材料与原件

1. **材料中心**：统一查询、预览、下载、上传版本和删除电子材料；
2. **文件详情/预览**：展示元数据、预览和历史版本；
3. **材料上传**：使用弹窗或抽屉，不设独立菜单页。

### 2.4 日期与提醒

1. **日期台账**：统一保存计划日期、截止日期和实际完成日期；
2. **提醒日历**：以日历展示专利、软著、商标、费用和自定义事项；
3. **新建/编辑提醒**：使用弹窗或抽屉。

日期由用户录入；未经确认，不开发法定期限自动推算。

### 2.5 费用与发票

1. **费用台账**：保存应付、实付、日期、收付款主体、状态和凭证；
2. **发票管理**：保存票面信息、报销状态、原件状态和电子发票；
3. **登记费用、登记发票**：使用弹窗或抽屉。

### 2.6 统计分析

1. **综合统计**：全部知识产权、类型、状态、年度、项目及费用概览；
2. **专项统计**：专利、软著、商标和费用统计，可通过同一页面的页签实现；
3. **年度趋势**：按创建时间汇总（口径随接口返回，正式口径确认后可改为业务日期）；
4. 支持按已确认条件筛选和导出 Excel。

每个指标在实现前必须定义数据来源、过滤条件、日期字段、去重规则和空数据行为。

### 2.7 基础资料

通过一个页面的页签维护：

- 权利人；
- 代理机构；
- 项目/产品。

人员即系统用户，不在基础资料中单独维护；搜索、新建、编辑、删除统一在系统管理的“用户”页签完成。

### 2.8 数据与系统管理

- 数据导入集成在工作台弹窗中；支持 UTF-8 CSV 和 XLSX 第一个工作表，模板列为 `我方文号,申请号,案件名称,专利所有权人,官费应缴纳日,本次官费缴纳至,本次官费缴纳金额,缴纳日期`，只有「案件名称」必填；其余列留空时不创建对应数据；
- 列表结果导出；
- 用户和角色；
- 简单角色权限；
- 数据字典；
- 操作日志；
- 系统设置。

## 3. 已确认核心数据

### 3.1 知识产权主档共性字段

- 稳定系统 ID；
- 名称；
- 类型（专利/软著）；
- 综合状态；
- 所属项目/产品；
- 内部负责人；
- 备注；
- 创建、修改及逻辑删除审计字段。

状态枚举和必填规则尚待确认。内部档案编号字段已按 D-018 彻底删除。

### 3.2 专利信息

候选字段：

- 专利名称、专利类型、专利摘要、技术领域；
- 申请国家/地区、申请号、申请日；
- 公开号、公开日；
- 专利号、授权日、期限届满日、法律状态；
- 申请人/专利权人、发明人/设计人、联系人；
- 代理机构、代理师。

“候选字段”来自已讨论页面方案；具体必填性、唯一性和枚举在数据模型定稿前确认。

### 3.3 软著信息

候选字段：

- 软件全称、简称、版本号、分类、用途、技术特点；
- 开发语言、运行平台；
- 开发完成日、开发方式、权利取得方式；
- 是否发表、首次发表日和地点；
- 申请日、受理日、登记号、登记日、证书编号、证书获得日期（界面统一显示为「授权公告日」，存储与接口字段仍为 `certificate_date`）；
- 补正日、补正截止日、办理状态；
- 著作权人、联系人、代理机构。

具体必填性、唯一性和枚举在数据模型定稿前确认。

### 3.4 商标/Logo信息

候选字段：

- 商标名称、商标文字、Logo图样、图样说明；
- 商标类型、颜色说明、申请国家/地区；
- 申请号、申请日期、注册号、注册日期、有效期开始日、有效期截止日；
- 商品/服务类别及项目；
- 商标申请人/权利人、联系人、代理机构和代理人；
- 电子注册证、纸质证书原件、保管位置和保管人。

分类体系、法域、状态枚举、续展规则和字段必填性尚待确认。原型中的类别和日期仅作布局示意。

### 3.5 已取得权利与证书文件

- 已取得权利状态直接记录在知识产权档案中；
- 专利证书、软著登记证书、商标注册证的电子扫描件作为材料中心的材料分类保存；
- 第一阶段不管理纸质证书领取、借出、移交和保管流程；
- 历史证书后端数据结构暂保留用于兼容已有数据，但不提供独立前端页面。

### 3.6 关联信息

每一项知识产权可以关联：

- 多个权利人；
- 多个人员；
- 多份材料及其版本；
- 多个日期和提醒；
- 多笔费用；
- 多张发票；
- 多份证书扫描件材料；
- 多条操作日志。

一张发票允许关联一笔或多笔费用，采用关系记录，不拼接 ID。

## 4. 文件和原件定义

- **电子材料**：上传到系统的 PDF、Office、图片等文件；
- **纸质原件**：现实中保管的证书、票据等；第一阶段不在系统内管理其领取、借出、移交和保管；
- **原件扫描件**：纸质原件扫描形成的电子材料。

专利材料候选分类：技术交底、检索报告、申请文件、官方通知、答复文件、授权文件、专利证书、缴费凭证、发票、其他。

软著材料候选分类：申请表、软件说明书、源程序、身份证明、权利归属证明、受理通知、补正通知、补正材料、登记证书、缴费凭证、发票、其他。

商标材料候选分类：Logo图样、商标申请书、主体证明、委托书、受理通知、审查文件、公告文件、商标注册证、续展材料、缴费凭证、发票、其他。

分类由数据字典维护，最终值可在开发对应模块前确认。

## 5. 简化权限目标

第一版角色只保留三种：

- 系统管理员（`admin`）；
- 管理员（`ip_admin`）；
- 普通用户（`user`）。

系统管理员与管理员可写；普通用户只读。数据查看不按部门限制，所有登录用户可查看全部档案；最终的写操作权限矩阵尚待确认。

## 6. 非功能要求

- 关键操作可审计；
- 文件下载、预览、导出需要鉴权；
- 密码和敏感信息安全保存；
- 金额采用精确定点类型；
- 业务日期与操作时间正确区分；
- 删除默认逻辑删除；
- 列表具备加载态、空态和错误态；
- 不用模拟数字冒充真实统计数据；
- 测试数据必须虚构并明确标识；
- 当前原型只面向桌面端，不设计移动端页面。

## 7. 第一阶段非目标

- 复杂工作流和流程设计器；
- 自动法律意见或法律状态结论；
- 未经人工确认的法定期限自动入库；
- 专利诉讼、许可、质押和价值评估；
- 官方机构或发票平台对接；
- OCR/AI 识别结果自动成为正式数据；
- 微服务架构；
- 自研 Office 在线编辑器。

## 8. 需求变更规则

新增知识产权类型、页面、核心字段、状态、角色、统计口径或外部集成时：

1. 先记录需求和影响；
2. 由用户明确确认；
3. 更新本规格与 `docs/DECISIONS.md`；
4. 再修改模型、接口和页面。
