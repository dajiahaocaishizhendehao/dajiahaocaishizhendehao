## D-013 基础资料优化：人员与系统用户合并、保留部门数据范围

- 状态：已替代（部门范围部分由 D-014 替代）
- 日期：2026-11-11
- 决策：
  1. 基础资料页面取消“部门”页签和部门维护入口，但数据库 `departments` 表、`department_id` 字段及“按部门可见”的数据范围逻辑继续保留。
  2. 基础资料“人员”页签直接读写系统用户（`users`），人员姓名即用户 `display_name`；原 `persons` 表继续保留给档案的发明人 / 设计人关联，不再在基础资料中单独维护。
  3. 权利人、代理机构、项目 / 产品支持新建、编辑和删除；删除采用逻辑删除并写审计。
  4. 人员页签仅系统管理员可见和操作；`ip_admin` 仍可维护其他三类基础资料。
  5. 受限角色（`dept_user`、`viewer`）新建或编辑时必须指定部门，避免出现看不到任何档案的账号。
- 依据：用户要求优化基础资料并删除部门，明确“人员与系统用户合并”，并在澄清中选择“页签统一”和“保留部门范围”。
- 影响：基础资料不再提供部门管理；部门归属改在系统管理的用户表单中维护。原 `persons` API 仍保留，供档案发明人 / 设计人关联使用。

## D-015 角色精简为三种

- 状态：已确认
- 日期：2026-11-11
- 决策：
  1. 角色只保留 `admin`（系统管理员）、`ip_admin`（管理员）、`user`（普通用户）三种。
  2. 删除 `dept_user`（部门用户）与 `viewer`（普通查看用户）；两者原本都是只读，统一合并为 `user`。
  3. 写权限不变：`admin`、`ip_admin` 可写；`user` 只读。系统用户管理仍仅 `admin` 可用。
  4. 新增迁移 `0008_merge_user_roles`，把历史库中的 `dept_user` / `viewer` 更新为 `user`；降级时 `user` 统一回退为 `viewer`（原部门用户无法精确还原）。
  5. 前端角色显示与下拉选项同步为“系统管理员 / 管理员 / 普通用户”。
- 依据：用户明确要求“人员的角色只保留：系统管理员，管理员和普通用户”。
- 替代：D-014 第 4 条中“角色标识保留”的描述由本决策替代。
- 影响：历史账号权限不扩大也不缩小，仍为只读；仅角色取值发生变化。

## D-017 新建档案不再要求填写内部编号

- 状态：已替代（D-018 进一步彻底删除该字段）
- 日期：2026-11-11
- 决策：
  1. “全部知识产权 → 新建档案”抽屉删除“内部编号”字段，案件名称移到表单第一项；商标 / Logo 页“新建商标”抽屉同样删除内部编号，商标名称移到第一项。
  2. 后端 `AssetCreate.asset_no` 改为可选；未提供时生成 `AUTO-YYYYMMDD-XXXXXXXX` 格式的系统编号，保证唯一。
  3. 调用方显式传入 `asset_no` 时保持原有唯一性校验，重复仍返回 409；编辑档案不修改内部编号。
  4. 编号规则尚未确认（Q-004），`AUTO-` 仅是不重复的系统占位编号，不代表业务或法律编号。
- 依据：用户明确要求新建档案时删除内部编号字段、不需要填写，并把案件名称放到最上面；随后确认商标页一并取消。
- 影响：前端所有新建档案入口都不再要求内部编号，编号统一由系统生成。

- 依据：用户明确要求“档案详情内的内部编号也要一并删除，同时，将全部的内部编号字段删除”，并在澄清中选择“彻底删除数据库字段”。

- 影响：外部调用方继续传 `asset_no` 会被忽略而不报错；依赖编号检索或导出的既有流程需改用案件名称 / 我方文号。
